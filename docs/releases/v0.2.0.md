# agda-native-air v0.2.0

+  **Date**: 2026-10-14, the first release of the software; the two earlier
   tags, `agda-algebras-corpus-v0` and `agda-algebras-corpus-v0.1`, are
   corpus data releases.
+  **Commit**: [`3de85b40`], the merge of [#250] on 10 October 2026, with
   four documentation commits on top of it on the branch `release-0.2.0`:
   the citation metadata of [#278], the author's ORCID and a `message` that
   reads on Zenodo, the README's paths and Agda badge, and these notes.
+  **Server**: `agda-mcp` 0.2.0.
+  **License**: Apache-2.0 for the code, CC-BY-4.0 for the documentation.

This release is the environment as it stood on 10 October 2026 at commit
[`3de85b40`].  Its center is the `agda-mcp` server, a Model Context Protocol
(MCP) server that gives an AI coding agent Agda's verdicts, goals, scope and
corpus search over stdio.  The release is cut at that commit, not at the head
of `main`, because the server built from it is the one that a private formal
development of about 15,000 lines of literate Agda used: the maintainer built
it on 10 October and ran it, never rebuilt, in the development's sessions
through 14 October, and the paper in preparation on that development cites
this version.  `main` has changed the server since (see below); later releases
tag `main`.

## Why this commit

The evidence is recorded on [#279]; in short, it is as follows:

+  The maintainer's checkout of this repository was pulled to `3de85b40` at
   14:20:39 MDT on 10 October 2026, by its reflog, and the server binary under
   `agda-mcp/dist-newstyle/` was built at 14:21:58, 79 seconds later.  The
   pull changed nothing under `agda-mcp/`.
+  A GHC interface file (`.hi`) records the MD5 hash of the source file it was
   compiled from.  All 21 of that build's interfaces (20 library modules and
   the executable's `Main`) carry the hashes of the files at `3de85b40`, and
   are byte-identical to those of a clean build of this release, so the binary
   was built from exactly these sources, with no uncommitted edit.  The
   binary itself cannot be reproduced byte for byte: its run path names the
   checkout, which moves everything after it when the path's length differs,
   and its data and symbol tables vary with the build directory's history.  A
   clean build differs from it in a few thousand of its 8.3 million bytes at
   a path of the same length, and in most of them at a longer one.  The
   interfaces are the record.
+  The binary has not been rebuilt since: nothing under
   `agda-mcp/dist-newstyle/build/` is newer than 14:21:58 that day, and the
   only later writes under `dist-newstyle/` are the planning caches that
   `cabal list-bin` writes.  `scripts/run-server.sh` builds nothing; it runs
   the binary that `cabal list-bin` names.  So the checkout went on
   serving this build after it was pulled past [#248], and every call that
   the development's sessions made to the server went to it.

## What it contains

### The `agda-mcp` server, version 0.2.0

Its tools at this commit, as its [README] lists them, are as follows:

+  four core proof-state tools: `get_goal`, `fill_hole`, `check_file` and
   `get_diagnostics`;
+  the whole-project gate, `check_project`, which runs a project's own
   acceptance command and reports its verdict without misreporting its exit
   code;
+  five live queries answered by a persistent `agda --interaction-json`
   process: `type_of`, `normalize`, `resolve_name`, `definition_of` and
   `exports_of`;
+  three corpus-backed search tools, registered by `--corpus`:
   `search_by_name` (whose `inScopeAt` answers which names a file can write),
   `search_by_type` and `get_dependencies`; a fourth, `search_in_scope`, is
   registered with them and presented only when `--expose` names it;
+  `auto`, Agda's own proof search at a hole, registered by `--auto`.

A client sees ten tools by default and thirteen with `--corpus`.  The server
does not link Agda as a library: it runs the `agda` executable it is given
(`--agda-bin`, else `agda` on the path), so a project can be checked with its
own pinned Agda, and it reads the diagnostics of both Agda 2.8.0 and 2.9.0.

### The toolchain

The flake at this commit pins the following:

+  Agda 2.9.0, not yet released at the time: agda/agda at `da66a8c7`, the
   `nightly` of 5 October 2026 ([#246] moved the repository to it);
+  the standard library 2.3, patched to check under Agda 2.9.0:
   formalverification/agda-stdlib at `fb5d1840`, tag `v2.3-agda-2.9.0`;
+  GHC 9.10.3 and cabal-install 3.16.0.0, from the nixpkgs that Agda's own
   flake pins (25.11);
+  nixos-unstable at `9dcb002c` for the Agda package set that the standard
   library is built in;
+  agda-algebras at `4662373d`, registered as a library in the dev shells;
+  JDK 21, sbt and Python 3.11 from nixos-24.05, for the Scala and Python
   parts.

`nix develop` needs Nix 2.28 or later and fetches the toolchain prebuilt from
the `formalverification` Cachix cache.  The release was built and run on
x86_64-linux.

### The corpus

The search tools read a corpus of definitions extracted by `agda-strux`.  The
one used with this release is the agda-algebras corpus v0.1, published as the
data release [`agda-algebras-corpus-v0.1`]: 13,123 rows extracted from
ualib/agda-algebras at `4662373d` under Agda 2.8.0, described by its
[dataset card].  The server indexes 11,865 of them, one per qualified name,
as the card explains.

## What `main` has changed since

+  [#248] (pull request [#257]): `get_goal` and `type_of` print in Agda's
   `Simplified` display mode by default, where this release always prints
   `Normalised`; a new `rewrite` argument chooses the mode, and each answer
   names it.
+  [#249] (pull request [#256]): `scripts/run-server.sh` runs a prebuilt
   server directly, without entering `nix develop`, when `AGDA_MCP_BIN` and
   `--agda-bin` are both given.

Everything else merged since is documentation, field reports and the agent
benchmark; the flake and its pins are unchanged.  The server on `main` still
reports version 0.2.0, so the version string alone does not tell a build of
`main` from this release's; name the tag or the commit.

## Build and run

```sh
git clone https://github.com/formalverification/agda-native-air
cd agda-native-air
git checkout v0.2.0
nix develop .#backend --command bash -c 'cd agda-mcp && cabal build exe:agda-mcp'
make agda-mcp-smoke     # initialize and tools/list against the built server

# the corpus, for the search tools (data/corpora/ is ignored by git)
gh release download agda-algebras-corpus-v0.1 \
  --repo formalverification/agda-native-air \
  --pattern corpus.jsonl.gz --dir data/corpora/agda-algebras/v0.1
gunzip -k data/corpora/agda-algebras/v0.1/corpus.jsonl.gz
```

An MCP client starts the server through `scripts/run-server.sh`, which enters
`nix develop .#backend`, runs the binary that `cabal list-bin exe:agda-mcp`
names (or `$AGDA_MCP_BIN`, when that is set), and passes its own arguments
on; it builds nothing, so build first.
Started from the checkout's root with `--corpus
data/corpora/agda-algebras/v0.1/corpus.jsonl --timeout 600`, it presents
thirteen tools.  The private development's sessions started it from the
development's own checkout, with that project's Agda by `--agda-bin`, the
corpus above by `--corpus`, a 600-second bound on each check by `--timeout`,
and the project's own acceptance command as the whole-project gate by
`--check-command`.  The server's [README] documents every flag, and its
sections [Configuring MCP Clients] and [Checking a client project with its
own toolchain] give example registrations.
