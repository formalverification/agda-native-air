# 2026-11-10, lean2agda issue 31: probes of an operation table for Lean's accelerated arithmetic

+  **Date**: 2026-11-10.
+  **Harness**: Claude Code 2.1.322.
+  **Model**: Claude Opus 5.5 (Anthropic).
+  **Effort**: high.
+  **Repository**: formalverification/lean2agda.
+  **Issue or pull request**: issue 31.
+  **Tools called**: check_file 6.

The session mapped each operation Lean's kernel computes on numerals
(`Nat.add`, `Nat.sub`, `Nat.mul`, `Nat.div`, `Nat.mod`, `Nat.gcd`, the
bitwise operations and the shifts) to an Agda definition over Agda's
`BUILTIN` naturals, so that the translator's profile U scaffold stops
computing them in unary.  The hand-written Agda was four probe files,
each a complete module with no holes: one that states every equation
Lean's kernel accepts on variables by `refl` under `--safe
--cubical-compatible` and computes on numerals past 2^64 (accepted), one
that shows the builtin monus losing Lean's `Nat.sub` equation at a
successor (rejected, intended), one that restores it with rewrite rules
under `--rewriting` (accepted), and one that shows `BUILTIN CHAR` refusing
a record (rejected, intended).  A fifth, scratch probe, written after a
measurement refused `Nat.zero_sub`, tested whether two more rules make
`Nat.sub`'s rules confluent with the monus's own clauses, and the rewrite
probe was rewritten to the three rules.  The rest of the Agda the session checked
was emitted by the translator, trees of up to 281 modules, and went
through the project's own drivers with a heap bound, not through
agda-mcp.

+  **Tools used**.  `check_file` once per probe, each answering in 69 to
   191 ms: the table's probe green with no diagnostics; the monus probe
   red with one `UnequalTerms` at line 33, whose `involved` field carried
   the two sides (`Nat:sub-builtin n (Nat:succ m)` against
   `Nat:pred (Nat:sub-builtin n m)`), the evidence the probe exists to
   record; the rewrite probe green; the character probe red with
   `BuiltinMustBePostulate` and Agda's sentence for it.  Two calls more,
   on the scratch probe of the three rules (117 ms) and on the rewritten
   probe (73 ms), both green.  Agda's `--local-confluence-check`, which
   the session ran from the command line on two variants of the scratch
   probe, named the critical pair (`Nat:sub-builtin (Nat:succ n₀)
   (Nat:succ m₁)` reducing two ways) with the rules declared one pragma at
   a time and passed with the three in one pragma; `check_file` would have
   given the same answer through the file's `OPTIONS` line, which is where
   the committed probe carries the flag.
+  **What worked**.  The verdict as Agda's exit code and the diagnostic's
   code were exactly what a probe's first line records ("rejected,
   `[UnequalTerms]`"), so the outcome line of each file was copied from
   the answer, not read off a terminal.  The `involved` sides of the
   `UnequalTerms` made the rejected probe's point without opening the
   message.  No library was needed, and the server's registration (the
   checkout's own Agda and library file) found the dev shell's Agda with
   nothing set.
+  **What was awkward or missing**.  Nothing in these four calls.  The
   work's real Agda load, trees of emitted modules checked under an 8G
   heap bound with a loop that refuses and retries declarations, is out
   of the server's scope by design, and the session did not try to route
   it there.  `normalize` might have shown the stuck normal forms the
   table removes (a field whose type mentions `v % 16`), but the probes
   were settled by checking, and the session did not call it.
+  **Command line comparison**.  For these probes, equal: one call per
   file against one `agda` run, with the answer already structured.  For
   the emitted trees, the command line (the project's `agda_check.py`,
   detached under `setsid`) was the only loop, since checks there run
   from minutes to an hour.
