# 2026-11-01, a private repository: a generated 8,000-line module and four written by hand, through check_file, with costs measured from the command line

+  **Date**: 2026-11-01.
+  **Harness**: Claude Code 2.1.316.
+  **Model**: Claude Opus 5.5 (Anthropic), which made every agda-mcp call;
   the session's first seven minutes, reading and running scripts with no
   agda-mcp call, ran on Claude Fable 5.1 (Anthropic).
+  **Effort**: max for the second model; not recorded for the first.
+  **Repository**: a private repository.
+  **Issue or pull request**: not named.
+  **Tools called**: check_file 33, normalize 6.

The session wrote five new modules and assembled them into one theorem,
all under `--safe`: one generated by a script in the repository (about
8,300 lines, most of them tables of about 7,600 clauses, which the script's
own tests compare with what it generates) and four written by hand, of 150
to 800 lines.  It developed every one of them through `check_file`, a module
at a time, and went to the command line only to measure: per-module and
per-definition profiles, peak memory, and the full check of the library
(181 modules).

+  **Tools used**.  `check_file`, 33 calls, 17 accepted and 16 rejected,
   none timed out; the median answer took 1.4 s, and the two longest,
   9.6 s and 8.5 s, included rechecking three edited dependencies.  The rejections, by the first error's code:
   `ClashingDefinition` 5, `NotInScope` 3, `UnequalTerms` 2,
   `ConstructorPatternInWrongDatatype` 2, and one each of `UnequalTypes`,
   `AmbiguousName`, `CoverageIssue` and `UnsolvedConstraints` (with
   `UnsolvedMetaVariables` beside it).  The generated module was first
   checked from the command line, with GHC's `-s` statistics, to see what
   it cost as generated; those runs found a literate-syntax error
   (`WrongContentBlock`) and a non-exact split in the generator's output,
   and once they were fixed the module was accepted on its first
   `check_file`, in 2.5 s.  `normalize`, 6 calls: the first
   on a file loaded it (1.1 s and 2.2 s on two files), the next took 3 to
   8 ms on the reused lane, and one was refused because the session passed
   the expression under the wrong key; the refusal named the key it
   expected.
+  **What worked**.  Every rejection named its cause precisely enough to
   fix in one edit, though the next could be the same cause elsewhere.  `ClashingDefinition` carried `involved.candidates`
   with the earlier definition's file and range, which showed at once that
   the clash was with a constructor exported by an opened module, not with
   anything in the file; `ConstructorPatternInWrongDatatype` showed the
   same cause from the other side, a pattern variable read as a
   constructor of that module.  A verdict with only a warning
   (`ModuleDoesntExport`, from an import list naming one name too many)
   came back `success: true` with the warning listed, as designed.  A
   module whose dependencies had changed was rebuilt in the same call, with
   no `reload` needed, since `check_file` runs a fresh Agda each time.
+  **What was awkward or missing**.  The repository requires each module's
   own check time, so the session deleted the new modules' interface files
   by hand and ran Agda from the command line, twice with
   `--profile=modules` and once with `--profile=definitions`, about 10 s a
   run, and used `/usr/bin/time -v` for peak memory.  A `check_file`
   option that returns Agda's profile table as data, with a way to ignore
   the existing interfaces of named modules, would have kept that inside
   the server.  One `normalize` of a pair returned a normal form whose
   second component was an unsolved metavariable (`_30`), with no field
   saying so; the component normalized alone gave a closed term.  A flag
   for unsolved metavariables in a normal form would have caught it.  The
   five clashes came from one cause over three checks, one clash per
   check, since Agda stops at the first scope error; an explicit import
   list ended them.
+  **Command line comparison**.  For the development loop the server was
   the more efficient one: its answers took as long as the command line's
   checks, and the structured code, range and candidates saved reading
   Agda's prose each time.  For measurement the command line was the only
   loop, since the server passes no profiling option and reports no
   memory.
